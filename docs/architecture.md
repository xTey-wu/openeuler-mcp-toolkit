# 架构与数据流

```text
支持 MCP 的大模型客户端
          │ stdio
          ▼
      FastMCP Server
          │
   ┌──────┼──────────────┐
   ▼      ▼              ▼
内存工具  文件系统工具     进程/调度工具
   │      │              │
   ▼      ▼              ▼
系统采集服务（psutil、/proc、受控文件访问）
   │
   └──────── 独立算法模块（页面置换、磁盘分配、CPU调度）
```

## 分层原则

1. `tools` 只负责 MCP 描述、参数约束和进度通知。
2. `services` 只执行只读系统采集，并将瞬时系统错误转换为清晰异常。
3. `algorithms` 不依赖 MCP 或宿主机状态，可以确定性测试。
4. `models` 定义公共输入输出，FastMCP据此生成 Schema。
5. `config` 在任何文件读取前执行路径边界检查。

## 信任边界

模型控制工具选择，但不能绕过工具参数验证。工具参数采用 `extra=forbid`，任何 Schema 外字段都会令调用失败，而不是被静默忽略。文件路径在 Server 内部解析并校验，模型无法调用删除文件、终止进程或更改系统配置的能力。

MCP 工具同时发布 `readOnlyHint=true` 和 `destructiveHint=false`。这些提示帮助客户端理解安全边界，但不是权限控制的替代品；真正的边界仍由 Server 只注册只读工具、限制文件根目录和校验参数来保证。

所有结果都可能被 MCP 客户端传给其模型提供方，因此“只读”并不等于“数据不会离开机器”。允许目录必须由用户显式控制。
